eink_uart 1.0.0

1. Purpose

APB UART in plain RTL with a 16 word transmit FIFO and a 16 word receive FIFO, for the 230400 baud link to the Seeed Grove triple colour e-ink display 1.54 inch (152 x 152 pixels). It replaces the library UART IP, which has no receive FIFO in this design. The format is fixed to 8N1, the block is polled (no interrupt) and has one clock (PCLK, 12 MHz in the reference design). The baud rate comes from a fractional tick generator and can be changed at run time. The BSP package eink_uart holds the UART driver, the display driver and the fonts.

5. Baud rate

A 16 bit phase accumulator adds BAUD to itself every PCLK; its carry is the 16x oversampling tick. A bit is 16 ticks, the receiver samples in the middle of a bit. At 12 MHz and BAUD = 20133 the rate is 230404 baud (+0.002 %). The BSP function eink_uart_set_baud(&u, 12000000, 230400) calculates the value in 32 bit integer arithmetic and returns the real baud rate (accurate to about 0.01 %). Only 230400 baud was tested.

6. FIFO behaviour

  • A full RX FIFO drops the NEW character and keeps the oldest 16 (sticky OVERRUN flag). The first characters after a flush are therefore never lost, whatever the time between two reads. At 230400 baud one character takes 43 us, so the 16 word FIFO tolerates about 690 us between two reads.
  • The TX FIFO accepts 16 characters; a write to a full FIFO is ignored (check TX full first).
  • Both FIFOs are built in distributed RAM (no block RAM).

8. Setting up the screen and streaming the data

The display is driven by the display driver eink154 on top of the UART driver. The driver renders the frame while it is streamed, so no frame buffer is needed (76 bytes of RAM for one chunk).

8.1 Display and protocol

ItemValue
Panel152 x 152 pixels, colours white, black, red. Row 0 is the top row, column 0 the left column. No partial updates
Frametwo 1-bit planes, first the black plane, then the red plane, 2888 bytes each (19 bytes per row, 152 rows). Most significant bit = leftmost pixel, 0 = ink, 1 = no ink. Red overrides black
Link230400 baud, 8N1. FPGA TX to display RX (F16), FPGA RX from display TX (F12)
Power-upthe display prints "firmware version:V1.1" at once and runs its self-test for 15 to 20 s
Handshakesend 'a' (0x61); the display answers 'b' as its first character, followed by the repeated text "UART_recv_func()" while it waits for data
Streamingright after the 'b': 2 x 2888 bytes in chunks of 76 bytes (4 rows), 80 ms pause after every chunk. The streaming takes about 6.5 s
Refreshwhen all bytes have arrived the display stops sending text and refreshes the panel (about 15 s). Keep at least 3 minutes between two frames (EINK154_MIN_REFRESH_MS)

8.2 Define the objects

A screen is a background colour plus two tables of pointers: EINK154_GRAPHIC_COUNT (2) graphics and EINK154_TEXT_COUNT (6) text blocks. The application owns the objects, the screen only points to them. A null pointer, or an object with enable = 0, is not drawn. Drawing order: background, graphics, then texts (texts are transparent).

ObjectFields
Graphic (eink154_graphic_t)enable, x, y, w, h and two bitmaps (black and red) in the panel encoding: row-major, MSB first, 0 = ink, a row takes (w + 7) / 8 bytes, padding bits 1. A red pixel is a 0 in the red bitmap and a 1 in the black bitmap. A graphic is opaque
Text block (eink154_text_t)enable, x, y (top-left), colour (EINK154_BLACK, EINK154_RED, EINK154_WHITE), scale 1 or 2, font id, text of up to 20 characters (ASCII 0x20 .. 0x5F, lower case is shown as upper case)

 eink154_screen_set_text(&screen, 1, &tilt_x);

8.3 Dynamic text (live values, no printf)

eink154_text_set_fixed(block, prefix, value, decimals, width, show_sign, suffix) writes prefix + number + suffix into a text block. The number is a fixed point value (value / 10^decimals), right aligned in width characters with spaces on the left, so the line keeps its width when the value changes. It returns -1 when the result had to be truncated.

 eink154_text_set_fixed(&tilt_x, "X:", tenths_of_degree, 1, 5, 1, " DEG");   /* "X:+12.3 DEG"  "X: -4.5 DEG" */
 eink154_text_set_fixed(&acc_x, "X:", milli_g, 0, 5, 1, " MG");              /* "X: +207 MG" */
 eink154_text_center(&tilt_x);                                               /* call again after a new text */

8.4 Initialise the driver, check and send

 static struct eink_uart_instance link;       /* display UART (this IP) */
 static struct eink154_instance   eink;       /* display driver */

 eink_uart_init(&link, UART1_INST_BASE_ADDR);                 /* ID check, flushes both FIFOs */
 eink_uart_set_baud(&link, 12000000, 230400);
 eink154_init(&eink, &link, &mtimer_inst);                 /* pointers to the UART and to the machine timer */
 eink154_set_hook(&eink, my_hook, 0);                         /* optional: called in every loop (LEDs) */

 eink154_check_t chk = eink154_screen_check(&screen);         /* up front: bounds, characters, collisions */
 if (chk.status == EINK154_OK) {
     eink154_stats_t stats;
     eink154_status_t rc = eink154_screen_update(&eink, &screen, &stats);   /* 'a' -> 'b', stream, monitor */
     printf("%s\n", eink154_status_str(rc));
 }

eink154_screen_update checks the screen again, refuses a frame that comes sooner than the minimum interval, sends the 'a', waits up to 30 s for the 'b', streams the two planes in 76 byte chunks with the 80 ms pauses and then watches the display for 2 s. stats.got_ack tells whether the 'b' arrived; stats.rx_after counts characters the display still sent after the last byte (at most 16, stats.rx_overflow = 1 for more): a display that keeps sending text points to a miscount of the bytes. Call it from a loop, for example every 4 minutes.

8.5 Layout rules and status codes

  • An object is the rectangle of the graphic, or the cell box of a text (characters without trailing spaces times the cell width of its font and scale, by the cell height). Touching edges are not an overlap.
  • eink154_screen_check refuses a screen with an object outside the 152 x 152 area, an unknown character, font or scale, or two enabled objects that overlap. It returns the status and the numbers of the offending objects: texts are numbered from 0, graphic g is -10 - g.

8.6 Test pattern

eink154_blocktest(&eink, phase, &stats) sends horizontal blocks of 8 rows without a screen structure (block k has the colour (k + phase) % 3: white, black, red; phase 1 = black, red, white). It is the quickest check of the wiring and the baud rate.

9. Verification

  • Simulation (QuestaSim, testbench/tb_apb_eink_uart.v): ID and BAUD reset value, loopback with 4 bytes in order, 16 bytes through the TX FIFO seen on the transmit line, RX overrun (20 bytes sent, the 16 oldest kept, flag set and cleared), external receive with a frame error, FIFO flush. Result: PASS.
  • Hardware: MachXO4 Companion board (LFMXO4-110HC-6BBG256I), 24 MHz CPU, 12 MHz APB, 230400 baud to the Seeed Grove e-ink display: handshake, frame streaming and screen refresh work.

10. Known limits

  • 8 data bits, no parity, one stop bit only.
  • No interrupt and no flow control; the FIFO depth is fixed at 16.
  • Only 230400 baud at 12 MHz was tested. The tick generator limits the baud rate to about f_PCLK / 16.
